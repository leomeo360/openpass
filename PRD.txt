# AI API Key 管理网关 PRD

## 1. 文档信息

| 项目   | 内容                                      |
| ---- | --------------------------------------- |
| 产品名称 | OpenPass                                |
| 产品类型 | AI API Key 管理与请求网关                      |
| 部署平台 | Cloudflare                              |
| 当前版本 | MVP v1.0                                |
| 主要用户 | 系统管理员、内部项目开发者                           |
| 核心目标 | 集中管理真实 AI API Key，并对不同项目进行独立授权、限额、统计和审计 |

---

## 2. 项目背景

目前存在多个网站或应用项目，共同调用 OpenAI、Gemini、Flux、Replicate、Claude 等第三方 AI 服务。

如果直接把真实的第三方 API Key 配置到每个项目中，会产生以下问题：

1. 无法准确知道每个项目使用了多少请求和额度。
2. 单个项目失控可能消耗整个账号的余额。
3. 真实 API Key 分散在多个项目中，存在泄漏风险。
4. 无法快速停用某个项目。
5. 无法统一切换供应商 Key。
6. 无法查询请求来源 IP、错误率、耗时和模型使用情况。
7. 多个真实 API Key 之间缺少统一的轮换、容灾和负载分配机制。

因此需要建立一个统一的 AI API 网关。

所有项目不再直接调用第三方 AI 平台，而是统一调用本系统，并使用本系统生成的虚拟 API Key。

---

## 3. 产品目标

### 3.1 核心目标

系统必须实现：

* 集中保存和管理真实 AI 供应商 Key。
* 为每个项目生成独立虚拟 Key。
* 按项目统计请求数量和预估费用。
* 按项目设置请求上限和金额上限。
* 超出额度后自动拒绝请求。
* 查看请求时间、模型、状态、耗时和来源 IP。
* 支持多个真实供应商 Key 的轮换与故障切换。
* 支持立即停用项目或吊销虚拟 Key。
* 防止真实供应商 Key 暴露给业务项目和最终用户。

### 3.2 非目标

MVP 阶段暂不实现：

* 面向外部客户的在线充值。
* Stripe 等支付系统。
* 自动开具账单或发票。
* 复杂的代理商分级体系。
* 完整的模型市场。
* 根据自然语言自动选择模型。
* 面向公众开放注册。
* 替代第三方供应商的正式账单。

系统内显示的费用属于根据内部价格表计算的预估费用，最终费用以供应商账单为准。

拥有全部权限：

* 管理 AI 供应商。
* 添加和删除真实 API Key。
* 创建项目。
* 生成和吊销虚拟 Key。
* 设置额度和限流规则。

MVP 阶段可以暂不开放独立账号。

* 查看剩余额度。
* 配置项目回调地址。

项目管理员不能看到真实供应商 API Key。

## 5. 核心概念

### 5.1 供应商 Provider

提供 AI 服务的平台，例如：

* OpenAI
* Google Gemini
* Anthropic
* Replicate
* Fal
* Together AI
* 自定义图片生成供应商

### 5.2 供应商凭证 Provider Credential

真实的第三方 API Key。

一个供应商可以拥有多个真实 Key，例如：

```text
OpenAI
├── openai-key-01
├── openai-key-02
└── openai-key-03
```

真实 Key 只能保存在服务器端，不允许返回给前端。

### 5.3 项目 Project

调用 AI 网关的业务系统，例如：

```text
AI 图片网站
AI 视频网站
CRM AI 助手
Chrome 主题生成器
游戏素材生成器
```

每个项目拥有独立额度、权限、虚拟 Key 和用量统计。

### 5.4 虚拟 Key Virtual Key

系统发给项目使用的 Key，例如：

```text
pk_live_xxxxxxxxxxxxxxxxx
```

项目调用网关时使用虚拟 Key，而不是供应商的真实 Key。

数据库只保存虚拟 Key 的哈希值，不保存可直接使用的明文。

虚拟 Key 创建成功后只完整显示一次。

### 5.5 模型 Model

具体可调用的 AI 模型。

每个模型需要配置：

* 模型名称。
* 所属供应商。
* 供应商模型 ID。
* 请求类型。
* 是否启用。
* 单次请求或 Token 价格。
* 支持的尺寸、质量和参数。
* 可使用的供应商凭证。

## 6. 产品整体架构

```text
业务项目
   ↓
虚拟 API Key
   ↓
Cloudflare Worker 网关
   ├── 身份验证
   ├── 项目状态检查
   ├── 权限检查
   ├── 频率限制
   ├── 额度检查
   ├── 请求记录
   └── 供应商路由
           ↓
Cloudflare AI Gateway / 第三方 AI API
           ↓
OpenAI / Gemini / Flux / Replicate / 其他供应商
```

推荐使用以下 Cloudflare 服务：

| 功能            | 服务                 |
| ------------- | ------------------ |
| API 网关        | Cloudflare Workers |
| 管理后台          | Workers 或 Pages    |
| 配置数据          | D1                 |
| 实时额度控制        | Durable Objects    |
| 指标统计          | Analytics Engine   |
| 大型请求或响应归档     | R2                 |
| AI 请求代理和供应商日志 | AI Gateway         |
| 管理后台登录        | Cloudflare Access  |
| 定时汇总          | Cron Triggers      |
| 异步任务          | Queues             |

### Key 字段

| 字段     | 说明               |
| ------ | ---------------- |
| Key 名称 | 例如 OpenAI 主账号 01 |
| 所属供应商  | OpenAI、Gemini 等  |
| Key 密文 | 加密保存             |
| Key 尾号 | 只显示最后四位          |
| 状态     | 启用、停用、异常         |
| 权重     | 用于负载分配           |
| 优先级    | 用于主备切换           |

| 最近使用时间 | 系统生成             |
| 最近错误   | 最近一次错误信息         |
| 健康状态   | 正常、限流、无余额、失效     |

* 后台不能再次显示完整真实 Key。
* 数据库不能保存真实 Key 明文。
* 日志中不得出现真实 Key。

* Key 状态变化必须写入审计日志。

| 项目描述    | 项目用途             |
| 状态      | 启用、暂停、停用         |

| 并发上限    | 最大同时请求数          |

| IP 记录方式 | 完整、脱敏、不记录        |

## 7.6 虚拟 Key 管理

每个项目可以拥有多个虚拟 Key，以区分不同环境或服务。

例如：

```text
PixelBloom Production
PixelBloom Staging
PixelBloom Background Worker
```

### 虚拟 Key 字段

| 字段     | 说明        |
| ------ | --------- |
| Key 名称 | 方便识别      |
| 所属项目   | 对应项目      |
| Key 哈希 | 用于身份验证    |
| Key 前缀 | 用于后台识别    |
| Key 尾号 | 用于后台识别    |
| 状态     | 启用、停用、已吊销 |
| 到期时间   | 可选        |
| 最后使用时间 | 系统生成      |
| 创建人    | 管理员       |
| 创建时间   | 系统生成      |

### 功能要求

* 创建虚拟 Key。
* 创建后只展示一次完整 Key。
* 复制完整 Key。
* 停用虚拟 Key。
* 永久吊销虚拟 Key。
* 设置到期时间。
* 查看该 Key 的请求统计。
* 支持一键轮换 Key。

轮换 Key 时：

1. 创建一个新 Key。
2. 旧 Key进入待停用状态。
3. 管理员完成项目配置切换。
4. 手动或到期自动吊销旧 Key。

## 7.7 请求认证

项目通过请求头提交虚拟 Key：

```http
Authorization: Bearer pk_live_xxxxxxxxx
```

网关收到请求后依次执行：

1. 读取虚拟 Key。
2. 计算 Key 哈希。
3. 查询对应项目。
4. 检查 Key 是否有效。
5. 检查项目是否启用。
6. 检查 Key 是否过期。
7. 检查项目是否有模型权限。
8. 检查 RPM 和并发限制。
9. 检查日额度和月额度。
10. 选择供应商和真实 Key。
11. 转发请求。
12. 记录请求结果和费用。

认证失败统一返回 `401`。

项目或 Key 被停用返回 `403`。

频率或额度超出返回 `429`。

## 7.8 模型权限管理

每个项目可以限制允许调用的模型。

例如：

| 项目           | 允许模型               |
| ------------ | ------------------ |
| PixelBloom   | Flux Pro、GPT Image |
| CRM AI       | GPT、Claude         |
| Video Studio | Kling、Veo          |
| 测试项目         | 仅低成本模型             |

项目请求未授权模型时，系统返回：

```json
{
  "error": {
    "code": "MODEL_NOT_ALLOWED",
    "message": "This project is not allowed to use the requested model."
  }
}
```

管理员可以设置：

* 项目允许的模型。
* 项目默认模型。
* 模型别名。
* 模型降级顺序。
* 单个模型独立额度。

## 7.9 供应商 Key 路由

系统需要支持多个真实 Key 的路由。

### MVP 支持的策略

#### 轮询

依次使用多个 Key。

```text
Key A → Key B → Key C → Key A
```

#### 权重分配

根据权重分配请求。

```text
Key A：50%
Key B：30%
Key C：20%
```

#### 主备切换

默认使用主 Key，主 Key 失败后使用备用 Key。

#### 自动跳过异常 Key

出现以下情况时暂时停止使用该 Key：

* 认证失败。
* 余额不足。
* 供应商限流。
* 连续请求失败。
* 管理员手动停用。

### 熔断规则

当一个 Key 连续失败达到指定次数：

* 将 Key 标记为异常。
* 暂停使用一段时间。
* 自动选择其他可用 Key。
* 记录告警。
* 到期后尝试一次健康检查。

## 7.10 额度与限流

系统需要支持四类限制。

### 请求频率限制

例如：

```text
每分钟最多 30 次
每分钟最多 100 次
```

### 并发限制

例如：

```text
同时最多进行 5 个图片生成任务
```

### 请求数量限制

例如：

```text
每天最多 2,000 次
每月最多 50,000 次
```

### 金额限制

例如：

```text
每天最多 $10
每月最多 $100
```

### 额度判断规则

请求开始前检查：

* 项目是否已经超出请求次数。
* 项目是否已经超出金额。
* 当前请求是否可能导致额度超出。
* 当前模型是否有单独额度。

请求完成后：

* 根据模型和实际参数计算费用。
* 更新项目日用量。
* 更新项目月用量。
* 更新虚拟 Key 用量。
* 更新模型用量。
* 更新供应商 Key 用量。

### 达到额度时的行为

支持以下策略：

* 直接拒绝请求。
* 自动切换到低成本模型。
* 仅发送告警但继续请求。

MVP 默认使用“直接拒绝请求”。

## 7.11 费用计算

系统维护独立的模型价格表。

### 价格类型

* 按输入 Token。
* 按输出 Token。
* 按图片数量。
* 按图片尺寸。
* 按图片质量。
* 按视频时长。
* 按音频时长。
* 按固定请求价格。
* 自定义计费单位。

### 费用记录

每条请求保存：

```text
预估费用
实际可计算费用
计费单位
使用量
价格版本
币种
```

模型价格变更后，历史请求必须继续使用请求发生时的价格，不能根据新价格重新计算。

## 7.12 请求日志

每次调用生成一条请求记录。

### 基础字段

| 字段         | 说明                  |
| ---------- | ------------------- |
| Request ID | 全局唯一请求编号            |
| 项目         | 请求所属项目              |
| 虚拟 Key     | 只记录 Key ID，不记录明文    |
| 供应商        | 实际调用的平台             |
| 供应商 Key    | 只记录内部 Key ID        |
| 模型         | 实际调用模型              |
| 接口         | 请求路径                |
| 请求时间       | 请求开始时间              |
| 完成时间       | 请求结束时间              |
| 耗时         | 总耗时                 |
| 状态         | 成功、失败、处理中           |
| HTTP 状态码   | 上游响应状态              |
| 来源 IP      | 根据项目策略记录            |
| 国家或地区      | 从 Cloudflare 请求信息获取 |
| User-Agent | 请求客户端               |
| 输入 Token   | 可选                  |
| 输出 Token   | 可选                  |
| 图片数量       | 可选                  |
| 视频时长       | 可选                  |
| 预估费用       | 系统计算                |
| 错误代码       | 请求失败时记录             |
| 错误摘要       | 脱敏后的错误信息            |

### 请求内容记录策略

每个项目可选择：

#### 仅元数据

不保存 Prompt 和 Response，只保存模型、状态、费用等信息。

#### 保存请求内容

保存 Prompt 和部分请求参数。

#### 保存完整请求和响应

用于测试和调试，不建议生产环境长期使用。

默认策略为：**仅保存元数据**。

### 隐私要求

* 不记录 Authorization 请求头。
* 不记录 Cookie。
* 不记录真实供应商 Key。
* 支持对敏感字段进行脱敏。
* IP 可以保存完整值、脱敏值或完全不保存。
* 完整请求内容需要设置自动删除时间。
* 大型图片或文件不得直接存入 D1。

## 7.15 告警

系统需要支持以下告警：

* 项目用量达到 70%。
* 项目用量达到 90%。
* 项目额度耗尽。
* 供应商 Key 认证失败。
* 供应商 Key 余额不足。
* 供应商 Key 连续失败。
* 项目错误率异常升高。
* 项目请求量突然增加。
* 单个来源 IP 请求异常。

MVP 告警方式：

* 管理后台通知。
* 邮件通知。

后续增加：

* Slack。
* 企业微信。
* Webhook。
* Telegram。

* 停用项目。
* 修改日志策略。

* 导出请求记录。

审计日志字段包括：

* 操作对象。
* 修改前内容摘要。
* 修改后内容摘要。
* 操作时间。
* 来源 IP。
* 操作结果。

审计日志不允许普通管理员删除。

## 8.2 异步任务

部分图片和视频供应商不会立即返回最终结果。

请求流程：

```text
项目提交生成请求
    ↓
网关创建任务
    ↓
调用供应商
    ↓
返回内部 Job ID
    ↓
项目轮询任务状态
    ↓
返回最终结果
```

任务状态：

* `queued`
* `processing`
* `succeeded`
* `failed`
* `cancelled`
* `expired`

异步任务必须记录：

* 项目。
* 请求 ID。
* 供应商任务 ID。
* 创建时间。
* 当前状态。
* 重试次数。
* 最终结果地址。
* 最终费用。

## 11. 非功能要求

### 性能

* 网关自身增加的 P95 延迟目标低于 100 毫秒，不包含供应商处理时间。
* 项目状态和虚拟 Key 查询应优先使用缓存。
* 后台请求日志查询不能阻塞网关请求。
* 大型响应内容不能直接写入 D1。

### 可用性

* 单个供应商故障不能导致整个网关不可用。
* 单个真实 Key 异常时应自动切换其他可用 Key。
* 日志写入失败时，不应默认阻断正常 AI 请求。
* 额度系统异常时采用可配置策略。

建议生产环境默认采用“额度检查失败则拒绝请求”，防止失控消费。

### 安全性

* 所有接口必须使用 HTTPS。
* 虚拟 Key 只保存哈希。
* 真实 Key 必须加密或保存于安全凭证服务。
* 管理后台必须受访问控制保护。
* 所有敏感管理操作记录审计日志。
* 任何日志都不能出现完整 API Key。
* 支持立即吊销虚拟 Key。
* 支持限制请求体最大尺寸。
* 支持来源 IP 黑名单。
* 后续支持项目 IP 白名单。

### 可观测性

网关自身需要记录：

* Worker 错误。
* D1 错误。
* Durable Object 错误。
* AI Gateway 错误。
* 供应商超时。
* 额度判断异常。
* 路由失败。
* 日志写入失败。

## 12. 核心业务流程

## 12.1 创建项目

1. 管理员进入项目页面。
2. 点击创建项目。
3. 填写名称和标识。
4. 设置允许模型。
5. 设置 RPM、每日额度和月度额度。
6. 设置日志策略。
7. 创建项目。
8. 系统生成第一个虚拟 Key。
9. 管理员复制虚拟 Key到对应项目。
10. 项目开始通过网关调用 AI。

## 12.2 正常请求

1. 项目发送请求。
2. Worker 验证虚拟 Key。
3. 系统查询项目。
4. 检查项目状态。
5. 检查模型权限。
6. 检查频率和额度。
7. 选择真实供应商 Key。
8. 转发请求。
9. 接收供应商结果。
10. 计算费用。
11. 更新使用量。
12. 写入请求日志。
13. 返回结果。

## 12.3 项目超额

1. 项目发起请求。
2. 系统发现已超过日额度或月额度。
3. 请求不再转发给供应商。
4. 返回 `429`。
5. 记录拒绝日志。
6. 创建额度告警。
7. 后台显示项目已超额。

## 12.4 供应商 Key 失败

1. 网关调用 Key A。
2. Key A 返回认证失败或限流。
3. 系统记录失败。
4. Key A 健康分下降。
5. 系统选择 Key B 重试。
6. Key B 成功后返回结果。
7. 后台请求详情展示切换过程。
8. Key A 连续失败后被临时熔断。

## 13. MVP 验收标准

系统达到以下条件后可以上线：

1. 管理员能够创建至少 20 个项目。
2. 每个项目可以生成独立虚拟 Key。
3. 虚拟 Key 创建后只完整展示一次。
4. 数据库不保存虚拟 Key 明文。
5. 项目无法调用未授权模型。
6. 管理员可以设置项目 RPM。
7. 管理员可以设置日请求上限。
8. 管理员可以设置月请求上限。
9. 管理员可以设置日费用上限。
10. 管理员可以设置月费用上限。
11. 超出限制后请求会被拒绝。
12. 管理员可以立即停用一个项目。
13. 管理员可以立即吊销一个虚拟 Key。
14. 一个供应商可以配置至少三个真实 Key。
15. 真实 Key 可以进行轮询或故障切换。
16. 请求日志可以按项目查询。
17. 请求日志可以显示来源 IP。
18. 请求日志可以显示模型、状态、耗时和费用。
19. 后台可以查看项目日用量和月用量。
20. 后台可以查看供应商 Key 的错误状态。
21. 管理操作会生成审计日志。
22. 请求和响应日志中不会出现真实 API Key。
23. 管理员可以关闭 Prompt 和 Response 内容记录。
24. 图片异步任务可以查询状态。
25. 单个供应商请求失败不会导致网关整体崩溃。

## 16. 最终产品边界

该系统的核心不是单纯保存 API Key，而是：

> 将多个真实 AI API Key 转化为可以按项目授权、限额、统计、审计和随时吊销的统一 AI API 服务。

MVP 应优先保证以下闭环：

```text
创建项目
→ 生成虚拟 Key
→ 项目调用 AI
→ 检查额度
→ 选择真实 Key
→ 记录请求
→ 统计费用
→ 超额自动停止
```

只要该闭环稳定，就可以投入内部生产使用。复杂计费、客户套餐和更高级分析功能可以在后续版本逐步增加。

下一步最适合把这份 PRD 拆成 **D1 数据库表结构、Worker API 接口清单、后台页面清单和 Codex 开发任务顺序**。
